## 🧭 How this organization is organized

### Repository naming

All repositories follow the pattern `<type>-<project>-<component>` (lowercase, hyphen-separated).

| Prefix | Purpose | Example |
|---|---|---|
| `app-` | Application / product | `app-crm-backend` |
| `lib-` | Shared library | `lib-auth` |
| `svc-` | Service / microservice | `svc-payments` |
| `infra-` | Infrastructure & deployment | `infra-docker` |
| `docs-` | Cross-project documentation | `docs-handbook` |
| `tpl-` | Repository template | `tpl-base` |
| `client-` | Client-specific project | `client-[name]-portal` |
| `lab-` | Experiments / proofs of concept | `lab-ai-search` |

### How we work

- **Fork + Pull Request:** external contributors fork the repository, work on a branch and open a PR. Only maintainers merge into `main`.
- **Branches:** `feat/…`, `fix/…`, `docs/…`, `chore/…` — short-lived, one topic each.
- **Commits:** [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:` …).
- **Versions:** [Semantic Versioning](https://semver.org/) with GitHub Releases.

Read [CONTRIBUTING.md](https://github.com/4DA-Company/.github/blob/main/CONTRIBUTING.md) before your first contribution.
